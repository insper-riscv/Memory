# boot_rom

Single-port internal ROM IP that holds the SoC boot program (the BOOT_ROM).

## 1. Role of the component in the SoC

The BOOT_ROM occupies the start of the address space (`0x00000000` to `0x00000FFF` in the default map, see [02-barramento-e-memoria.md](https://github.com/insper-riscv/Core/blob/main/docs/pt-br/contracts/02-barramento-e-memoria.md)) and gives the fetch stage the instruction of the PC when it points into that range. The content comes from the initialization file written by the full Quartus compilation; according to the VHDL header, no test rewrites it over JTAG, unlike the FLASH ([flash](flash.md)). The BOOT_ROM does not go through the instruction cache.

## 2. Interface

### 2.1. Generic

| Generic | Type | Default | Meaning |
| :--- | :--- | :--- | :--- |
| `size_bytes` | `positive` | 4096 | Size in bytes, a power of two; sets the width of `i_address` and the word count |

### 2.2. Ports

| Port | Direction | Width | Default | Meaning |
| :--- | :--- | ---: | :--- | :--- |
| `i_address` | input | $\log_2(\text{size\_bytes}) - 2$ | | Word index (byte address without the two low bits) |
| `i_clk` | input | 1 | `'1'` | Memory clock |
| `i_rden` | input | 1 | `'1'` | Read enable |
| `i_wren` | input | 1 | `'0'` | Write enable |
| `i_data` | input | 32 | zeros | Write data |
| `o_q` | output | 32 | | Word read |

## 3. Behavior

### 3.1. Library configuration

The read is done by the `altsyncram` instance of the `altera_mf` library, which belongs to Quartus and is not part of this repository. The parameters fixed in the VHDL are:

| Parameter | Value |
| :--- | :--- |
| `operation_mode` | `SINGLE_PORT` |
| `width_a` | 32 |
| `numwords_a` | $\text{size\_bytes} / 4$ (1024 by default) |
| `widthad_a` | $\log_2(\text{size\_bytes}) - 2$ (10 by default) |
| `init_file` | `./boot_rom_init.mif` |
| `outdata_reg_a` | `UNREGISTERED` |
| `read_during_write_mode_port_a` | `NEW_DATA_NO_NBE_READ` |
| `lpm_hint` | `ENABLE_RUNTIME_MOD=YES,INSTANCE_NAME=BOOT_ROM` |
| `intended_device_family` | `Cyclone V` |

### 3.2. Read latency

The address is captured on the edge of `i_clk` and the output has no extra register, so the word of the address applied on an edge appears on `o_q` after it, with one cycle of synchronous latency. The runtime modification hint (`ENABLE_RUNTIME_MOD`) keeps the memory visible to the Quartus In-System Memory Content Editor, and the instance shows up under the name `BOOT_ROM`.

### 3.3. Initialization file

The `.mif` is generated by the board build flow from the platform boot code. The IP size must agree with the BOOT_ROM limit configured in the core and in the platform configuration file.

## 4. Integration

The `.qip` file (`src/ROM/Cyclone-V/boot_rom.qip`) registers the IP as "ROM: 1-PORT", version 20.1, family Cyclone V, and points to the VHDL.

| Top | Instance | Wiring |
| :--- | :--- | :--- |
| DE0-CV board top (Insper-RISC-V) | `BOOT_ROM` | `i_address` on bits 11 to 2 of the fetch address, `i_clk` on the IF stage clock, `i_rden` on the fetch enable, `i_wren` at `'0'`, `o_q` on the core Boot ROM data |

In GHDL simulation the equivalent simulation model is [rom_simulation](rom_simulation.md).

## 5. Verification

No `tests/python/tests.json` entry covers this IP, because it needs Intel's `altera_mf` library, absent from the continuous integration image (see the [README](../../../README.en.md)). What exercises it is the hardware top simulation in the Tests repository. `make paths` checks that the `.qip` exists.
