# ram

## 1. Role of the component in the SoC

The internal RAM IP is the data memory of the core when the RAM sits inside the FPGA. It is a single-port memory with synchronous read and write and byte enables, implemented in device memory blocks by the `altsyncram` megafunction. The file was generated by the Quartus megafunction wizard (1-PORT RAM, version 20.1, Cyclone V family), with the size turned into a generic. The `altsyncram` library belongs to Quartus (the `altera_mf` library) and is not in this repository. According to the README of the repository, the IPs also simulate in GHDL through Intel's `altera_mf` models, and the general-purpose simulation model of the RAM is the one described in [ram_simulation.md](ram_simulation.md).

## 2. Interface

### 2.1. Generics

| Generic | Type | Default | Meaning |
| :--- | :--- | ---: | :--- |
| `size_bytes` | positive | 262144 | memory size in bytes, a power of two, which is what it occupies in the FPGA |

With $S$ equal to `size_bytes`, the memory has $S / 4$ 32-bit words, and the word address has $\log_2 S - 2$ bits.

### 2.2. Ports

| Port | Direction | Width | Meaning |
| :--- | :--- | ---: | :--- |
| `i_address` | input | $\log_2 S - 2$ | word address |
| `i_byteena` | input | 4 | byte enables of the write, default `1111` |
| `i_clk` | input | 1 | single memory clock, default `'1'` |
| `i_data` | input | 32 | write data |
| `i_rden` | input | 1 | read enable, default `'1'` |
| `i_wren` | input | 1 | write enable |
| `o_q` | output | 32 | read data |

With the default 256 KB, the address has 16 bits.

## 3. Behavior

### 3.1. `altsyncram` configuration

| Parameter | Value | Effect |
| :--- | :--- | :--- |
| `operation_mode` | `SINGLE_PORT` | one read and write port |
| `width_a` | 32 | data width |
| `numwords_a` | `size_bytes / 4` | number of words |
| `widthad_a` | $\log_2$ `size_bytes` $- 2$ | address width |
| `width_byteena_a` and `byte_size` | 4 and 8 | four byte lanes of 8 bits |
| `outdata_reg_a` | `UNREGISTERED` | the output has no extra register |
| `clock_enable_input_a` and `clock_enable_output_a` | `BYPASS` | no clock enable |
| `outdata_aclr_a` | `NONE` | no asynchronous reset of the output |
| `read_during_write_mode_port_a` | `NEW_DATA_NO_NBE_READ` | read mode at the same address as a write, defined by the Quartus library |
| `power_up_uninitialized` | `FALSE` | the memory starts zeroed |
| `lpm_hint` | `ENABLE_RUNTIME_MOD=YES,INSTANCE_NAME=RAM` | the content can be read and rewritten over JTAG with the Quartus memory content editor, through the instance named `RAM` |
| `intended_device_family` | `Cyclone V` | target family |

### 3.2. Latency

The address, the data and the enables are captured on the rising edge of `i_clk`, and the output has no register, so `o_q` presents the read word right after that edge, which makes the read latency 1 cycle. The core contract expects the internal RAM data in the cycle after the request (see the bus and memory contract of the Core repository).

### 3.3. Initialization

The generator references no initialization file (`MIFfilename` is empty in the IP header) and the `.qip` lists none. The folder holds an `init.mif` of 4096 32-bit words whose declared content is zero at addresses `00A` to `FFF`, which the IP does not use. With `power_up_uninitialized` at `FALSE`, the RAM starts with zeros, and `ENABLE_RUNTIME_MOD` allows the content to be rewritten over JTAG after the FPGA is configured.

The parameters `NUMWORDS_A` equal to 4096 and `WidthAddr` equal to 12 that the IP header still records come from the wizard configuration, and the instance uses the `size_bytes` generic.

### 3.4. IP files

| File | Content |
| :--- | :--- |
| `ram.vhd` | the entity and the `altsyncram` instance |
| `ram.qip` | lists `ram.vhd` and `ram.cmp` for Quartus, with the tool name `RAM: 1-PORT` |
| `init.mif` | image of zeros, referenced neither by the `.qip` nor by the `.vhd` |

## 4. Integration

| Item | Description |
| :--- | :--- |
| Instantiated in | `src/simulation/internal-mem/quartus/core_fpga_test.vhd` of the Insper-RISC-V repository, instance `RAM`, on the `pll_clk_idexmem` clock |
| Address | the byte address of the core RAM minus the RAM base (`0x00008000`), in words, truncated to 16 bits |
| Enables | `i_rden` and `i_wren` are those of the core RAM combined with the RAM enable and the negation of the UART selection, so a UART access does not reach the RAM |
| Data | `i_data` and `i_byteena` come from the RAM write signals of the core, and `o_q` returns to the core as read data |

The memory map, the internal RAM range (`0x00008000` to `0x3FFFFFFF` by default) and the ready contract of the bus are in the bus and memory contract of the Core repository. The instantiation order matters for the JTAG instance index of `RAM`, and `core_fpga_test` instantiates `FLASH_MEM` after it so as not to change the RAM index.

## 5. Verification

This IP has no cocotb test of its own and no entry in `tests/python/tests.json`, because the `altera_mf` library belongs to Quartus. The behavior of a single-port synchronous memory with byte mask is verified in the equivalent simulation model, described in [ram_simulation.md](ram_simulation.md). The paths of the `.qip` are registered in `paths.yaml`.
